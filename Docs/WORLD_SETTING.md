## 一、设定骨架

### 1.1 一句话定位 🎨

> 你是**主神空间**的一名调度者。你没有自己的身体，只有一批被从各个崩坏世界打捞回来的**素体**。
> 你把它们派进一个又一个濒临崩溃的位面，用从那些世界里剥下来的**词条**改造它们——
> 然后看着它们打，看着它们死，再决定下一个进去的是谁。

### 1.2 结构骨架（由已决机制反推，非创作）

设定必须承载以下五件已决的机制，缺一不可：

| 机制（已决） | 设定上必须提供的承载物 |
|---|---|
| 玩家**不参与**战斗（D-04 全自动） | 玩家不是战场上的人，而是**远程调度者**——这解释了为何无法微操 |
| 素体**无先天职业**，职业可装卸（D-08） | 素体是**空白容器/躯壳**，职业是外来的"权限模块" |
| 词条来自**不同世界**且可跨界融合 | 世界之间原本不相通，**主神空间是唯一枢纽** |
| 单局失败后**下一局重新开始**，但有长线积累 | **轮回**——失败不是终点，记忆与传承会留下 |
| 单局 = 1 个世界（D-22 ⬜） | 每次"任务"投放到一个指定位面 |

### 1.3 三个层级

```
┌─────────────────────────────────────────────┐
│ 主神空间 (Meta Hub)  ——  局外，永久          │
│   世界星图 / 素体大名单 / 传承保险库 / 科技树  │
└───────────────────┬─────────────────────────┘
                    │ 投放
┌───────────────────▼─────────────────────────┐
│ 位面任务 (World Run)  ——  单局，3 层         │
│   路线推进 / 素体招募 / 插槽装配 / 羁绊构筑    │
└───────────────────┬─────────────────────────┘
                    │ 遭遇
┌───────────────────▼─────────────────────────┐
│ 自动战斗 (Battle)  ——  单场，20~40 秒        │
│   零输入，纯观战                              │
└─────────────────────────────────────────────┘
```

### 1.4 关键设定问题 🎨

以下三个问题会显著影响文案基调，建议早定：

| 问题 | 选项 |
|---|---|
| **主神是什么** | 冷酷的系统 / 有人格的存在 / 身份成谜（可作为长线悬念） |
| **素体有没有自我意识** | 有（则阵亡有情感重量）/ 无（则可无负担消耗）/ 越强越有 |
| **玩家为何被困在这里** | 惩罚 / 交易 / 不明（无限流经典） |

> 推荐：**主神身份成谜 + 素体权能越高自我越强 + 玩家被困原因不明**。三者都留白，给后续内容更新留出空间，同时"高星素体开始反抗"是一个天然的叙事钩子。

## 四、元素环与各世界表皮

✅ 依据 [D-02](DESIGN_DECISIONS.md)。

### 4.1 内核枚举（唯一真值）

```csharp
public enum Element { None, Metal, Wood, Water, Fire, Earth }
```

**克制环**：

```
Fire → Metal → Wood → Earth → Water → Fire
（火克金，金克木，木克土，土克水，水克火）
```

| 关系 | 系数 |
|---|:---:|
| 攻击方克制受击方 | `1.25` |
| 受击方克制攻击方 | `0.75` |
| 无克制 / 任一方 `None` | `1.00` |

### 4.2 各世界显示表皮 🎨

| 内核枚举 | W-01 末日生化 | W-02 赛博蜂巢 | W-03 蜀山仙界 | W-04 旧日深渊 |
|:---:|---|---|---|---|
| `Metal` | 合金 | 纳米 | 金 | 星骸 |
| `Wood` | 菌毒 | 生体 | 木 | 孢生 |
| `Water` | 酸蚀 | 数据 | 水 | 潮汐 |
| `Fire` | 辐射 | 过热 | 火 | 燔祭 |
| `Earth` | 尘障 | 磁场 | 土 | 岩渊 |

### 4.3 ⚠ 实现铁律

> **映射表只作用于 UI 显示与特效选择，不得进入任何逻辑判断。**
> 克制关系判定永远走内核枚举 `Element`。
> 违反此条会导致同一套数值在不同世界产生不同结果，破坏配平与确定性。

## 八、LLM 文案口径约束

[ROGUE_WORLD 第七节](ROGUE_WORLD_AND_AFFIX_DRAFT.md) 已定义 LLM 沙盒。本节补充**文案层面**的硬约束：

### 8.1 必须遵守

1. **术语一致**：LLM 输出的所有文本必须使用第二、三、五节的术语，禁用第七节的废弃词；
2. **不得自创机制**：叙事文本中不得出现内核不存在的机制（暴击、格挡、闪避、连击等）；
3. **不得承诺数值**：文案中不得出现具体数值承诺（"使攻击力翻倍"），数值一律由 `system_effect` 结构化字段表达。

### 8.2 可复现性约束 ⬜ [D-20](DESIGN_DECISIONS.md)

```
种子系统预生成候选池 → LLM 只能从池中"选择" → 叙事文本自由发挥
```

- LLM **不得**自由指定 `affix_id`，只能返回候选池的**索引**；
- 候选池由 `Rng(seed, nodeId)` 预生成，与 LLM 是否可用无关；
- `narrative_text` 与 `choices[].text` 完全自由——**叙事不影响可复现性**；
- 离线兜底时直接用候选池 + 静态文案。

这保证"种子分享 / 每日挑战 / 速通排行"这些肉鸽标配功能保持可行。

### 8.3 提示词中应注入的固定上下文

调用 LLM 时，系统提示词应始终包含：当前世界代号与基调、当前层数与节点类型、出战小队的素体名称与已激活羁绊、本次可选的候选池条目（仅索引与名称）。**不得**注入具体数值与内核实现细节。
