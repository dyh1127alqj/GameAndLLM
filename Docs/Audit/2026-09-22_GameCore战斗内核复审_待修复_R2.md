## 三、🔴 仍未修复 / 编译已实测报错

```
HealPipeline.cs(34,28): error CS0234  命名空间"GameCore.Math"中不存在类型或命名空间名"Min"
DamagePipeline.cs(36,85): error CS0117 "DamageFlags"未包含"Blocked"的定义
DamagePipeline.cs(45,63)/(54,54)/(83,28)/(86,34)/(94,34)/(103,34): error CS0234 同上（Max/Min 各 6 处）
BattleSim.cs(73,37): error CS0117  "TargetResolver"未包含"ResolveTarget"的定义
BattleSim.cs(162,20): error CS1729  "BattleResult"不包含采用 8 个参数的构造函数
```

### 3.1 命名空间遮蔽导致 `System.Math` 不可用（新暴露，7 处报错）

`DamagePipeline.cs`、`HealPipeline.cs` 位于 `namespace GameCore.Pipeline` 下，同时又 `using GameCore.Math;`。由于项目本身把数学库所在命名空间起名为 **`GameCore.Math`**，C# 的外层命名空间成员查找规则会让 `GameCore.Pipeline` 内的裸写 `Math.Max(...)` / `Math.Min(...)` 优先解析成同级命名空间 `GameCore.Math`（通过外层 `GameCore` 命名空间可见），而不是 `System.Math` 类型——但 `GameCore.Math` 命名空间下没有名为 `Max`/`Min` 的成员，于是报 CS0234。

`BattleSim.cs` 里其实已经用 `global::System.Math.Min(...)` 完全限定规避了同样的坑，但 `DamagePipeline.cs`/`HealPipeline.cs` 这两个文件没有同步处理——说明修复提交本身也没有跑通一次完整编译就提交了，和首轮问题的根因（"未联调编译"）如出一辙。

**建议**：这是命名空间设计本身埋下的雷，逐处加 `global::System.Math.` 前缀只是治标；更彻底的修法是把 `namespace GameCore.Math` 改名（如 `GameCore.Combat` / `GameCore.Numerics`），从根上消除任何未来代码再次踩坑的可能。

### 3.2 `DamageFlags` 缺少 `Blocked` 成员

`DamagePipeline.CalculateAndApply` 无敌判定分支 `baseFlags | DamageFlags.Blocked`（[DamagePipeline.cs:36](../../src/GameCore/Pipeline/DamagePipeline.cs#L36)）引用的 `Blocked` 标记，在 `Enums.cs` 的 `DamageFlags` 定义里从未存在（现有值：`None/Direct/Dot/Reflected/Crit/Executed/ShieldAbsorb`）。`PipelineTests.Invincible_Blocks_All_Damage` 测试也依赖 `result.Flags.HasFlag(DamageFlags.Blocked)`。需要在 `DamageFlags` 里补一个 `Blocked = 1 << 6` 之类的标记位。

### 3.3 `TargetResolver.ResolveTarget` 方法名 + 参数顺序都对不上

`BattleSim.ExecuteTurn`（[BattleSim.cs:73](../../src/GameCore/Battle/BattleSim.cs#L73)）调用 `TargetResolver.ResolveTarget(u, TargetMode.Nearest, enemies, _lockTracker)`，但 `TargetResolver.cs` 里真实存在的方法叫 `ResolveSingleTarget`，且参数顺序是 `(attacker, allUnits, mode, tracker)` —— 名字和第 2/3 个参数顺序都不一致。这处代码从首轮提交起就是错的，本轮修复未触碰 `TargetResolver.cs` 也未修正调用点，属于遗留问题。

### 3.4 `BattleResult` 仍被当作有位置构造函数的类型来调用

`BattleContext.cs` 里 `BattleResult` 依旧是只含 `required init` 属性的普通 `sealed class`，没有定义任何构造函数。但 `BattleSim.RunToCompletion()`（[BattleSim.cs:162](../../src/GameCore/Battle/BattleSim.cs#L162)）用 8 个位置参数去 `new BattleResult(...)`。这正是首轮报告点名的"把 init-only 属性类当位置构造函数用"这一类错误，本轮修复只是把参数列表换了一套（加了伤害/技能统计），但没有解决"这个类根本没有构造函数"这个根本问题——要么给 `BattleResult` 补一个匹配的构造函数，要么把调用点改成对象初始化器 `new BattleResult { Outcome = ..., ElapsedTicks = ..., ... }`。

## 四、🟡 尚未被编译器报出、但人工审查已确认会炸的问题

因为 `GameCore.csproj` 本体还没编译通过，`GameCore.Runner` 和 `GameCore.Tests` 两个下游项目目前完全没被尝试构建。以下问题是逐行比对签名后人工确认的，建议和上面几项一起修，避免"修一层炸下一层"反复拉锯：

1. **`PipelineTests.cs` 的 `UnitSnapshot.Create(...)` 命名参数全对不上**（[PipelineTests.cs:11-21](../../tests/GameCore.Tests/PipelineTests.cs#L11-L21)）：调用用的是 `prof / atk / armor / speed / pos`，但 `UnitSnapshot.Create` 的真实形参名是 `profession / baseAtk / baseArmor / baseSpeed / boardPosition`（[UnitSnapshot.cs:104-117](../../src/GameCore/Model/UnitSnapshot.cs#L104-L117)）。这是本轮修复新引入的问题（把原来的位置构造函数调用改成了工厂方法调用，但命名参数抄错了名字）。
2. **`Program.cs` 引用了不存在的 `SkillDefinition.BaseValue`**（[Program.cs:84](../../src/GameCore.Runner/Program.cs#L84)）：`ss05.ActiveSkill = new SkillDefinition { ..., BaseValue = 250 }`，但 `SkillDefinition.cs` 里没有 `BaseValue` 这个属性（这里语义上应该是想设置治疗技能的 `HealRatioPermille`）。同样是本轮修复新引入的问题。
3. **`Program.cs` / `BattleSimTests.cs` 仍在用位置参数调用 `new BattleContext(...)`**（[Program.cs:24,60](../../src/GameCore.Runner/Program.cs#L24)、[BattleSimTests.cs:71](../../tests/GameCore.Tests/BattleSimTests.cs#L71) 等）：和 3.4 是同一类问题——`BattleContext` 也是只有 `required init` 属性、没有构造函数的类，本轮修复完全没有触碰这几处调用点。
