## 三、🟡 交接文档表述与代码现状不符

### 3.1 `README.md` 把"16 条战术指令判定器"标记为已完成，但代码里没有任何 Gambit 求值逻辑

`README.md` 路线图（本次提交新增）：

> 2. [x] **第二阶段：纯 C# 战斗内核与单元测试 (GameCore.Battle - Sprint 1)**
>    - 落地 8 步确定性伤害管线、10 大扩展机制与 **16 条战术指令判定器**；

`grep -r "TacticsSlot\|TacticsInstruction\|ConditionType\.\|ActionType\." src/GameCore` 只命中两个文件：`UnitSnapshot.cs`（字段声明）和 `TacticsInstruction.cs`（数据结构定义本身）。`BattleSim.cs`（战斗主循环）**没有任何地方读取 `TacticsSlot1`/`TacticsSlot2`**，`ExecuteTurn` 走的完全是写死的"大招>战技>普攻"基线判定，和 [BATTLE_CORE.md 15.3](../BATTLE_CORE.md#153-战前战术指令系统-gambit--d-04d) 要求的"指令槽1→指令槽2→内置默认AI"求值链路没有任何关系。这一点其实早在 [设计符合性审查 §3.5](./2026-09-22_GameCore战斗内核设计符合性审查_待修复.md#35-gambit-战术指令槽已建模但从未被求值) 就已经记录过，当时定性为"Sprint 1 范围外、待跟进"，现在 Sprint 1 已经被标记为 `[x]` 完成、README 又把"16 条战术指令判定器"写进了 Sprint 1 的完成清单——这个说法目前不成立：`TacticsInstruction.cs` 只是数据结构（四元组 + 1 个默认值），`ConditionType`/`ActionType` 枚举加起来一共只有 6+5=11 个值，且没有任何一处代码消费它们。"16 条"这个数字来自 `BATTLE_CORE.md` 15.3 对**设计规格**的描述（"首发 16 条原子战术指令"），不是已经写出来的判定器数量。

`HANDOVER_FOR_NEXT_SESSION.md` 的表述相对克制（"纯数据驱动强类型四元组...每素体开放 2 个战术槽"，没有直接说"已落地判定"），但也没有明确指出"求值逻辑完全没写"，容易被理解为已经可用。

**建议**：把 README 这一条改成如实反映现状的表述（例如"Gambit 战术槽数据结构已就绪，求值逻辑留待 Sprint 2.5 / Sprint 3 补齐"），避免下一个 session 在 Sprint 3 的 UI 工作里假设有一个能跑的 Gambit AI 后端可以对接。
