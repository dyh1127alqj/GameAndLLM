## 三、🟡 需修复的逻辑/设计问题（修复编译错误后仍需处理）

1. `ExecuteTurn`（`BattleSim.cs`）判断是否放技能写死 `CurrentRage >= 100` / `CurrentMana >= 100`，完全未读取 `SkillDefinition.ManaCost` / `RageCost` 字段——这两个字段定义了但从未被消费。
2. `_lockTracker`（索敌黏性锁）从未调用 `Tick()`，导致"1 秒黏性锁定"实际上永不过期，与 `TargetResolver.cs` 注释描述的设计不符。
3. `RunToCompletion()` 中 `TotalDamageDealt` 硬编码为 `0`，`BattleSim` 全程没有任何伤害/技能次数累加器；而 G1 门禁要求"人均技能释放 ≥ 2.0 次/场"，当前架构下该指标无法被实际计算。
4. `BattleContext.RandomSeed` 定义了但整个内核没有任何地方消费随机数（暂无暴击/闪避等随机机制，可先记为 TODO）。

## 四、修复建议（建议顺序）

1. **仓库卫生**：补充 `.gitignore`（`bin/`、`obj/`、`*.user` 等 .NET 忽略规则），`git rm -r --cached` 清除已提交的构建产物及 `runner_output.txt`。
2. **敲定统一类型契约**：以 `TargetResolverTests.cs` / `CombatMathTests.cs` 已采用、且与 Model 层定义吻合的「`required init` 属性 + 对象初始化器」风格为准，禁止位置构造函数；随后按第二节表格逐一修正 `BattleSim.cs`、`UnitSnapshot.cs`（补齐治疗加成字段）、`DamagePipeline.cs`（改调用名）、`Program.cs`、`PipelineTests.cs`、`BattleSimTests.cs`。
3. 给 `BattleResult` 补齐实际会被读取的字段（伤害统计 / 技能释放次数 / 存活数等），并在 `BattleSim` 中真正累加。
4. 让 `ExecuteTurn` 读取 `skill.ManaCost` / `RageCost`，而非写死 100；在 `Step()` 中调用 `_lockTracker.Tick()`。
5. **流程性根因修复**：接入 CI（如 GitHub Actions），在 PR / push 时跑 `dotnet build && dotnet test` 作为合入门禁，避免不能编译的代码再次进入 `main`。
