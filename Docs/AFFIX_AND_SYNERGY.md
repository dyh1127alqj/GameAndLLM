## 一、插槽拓扑与词条分类

### 1.1 插槽类型定义 ✅ [D-25](DESIGN_DECISIONS.md)

| 插槽类型 | 英文标识 | 允许镶嵌 | 说明 |
|---|---|---|---|
| **核心槽 (Core Slot)** | `Slot_Core` | **职业词条** 或 **血脉词条** | **每素体恒为 2 个**。"身份槽"——决定该素体的战术职能与世界血统 |
| **作战槽 (Combat Slot)** | `Slot_Combat` | 技能词条 / 触发型战技 | 提供由法力驱动的局内主动战技与触发机制 |
| **通用槽 (Utility Slot)** | `Slot_Utility` | 属性增幅 / 机制改造 | 纯数值底盘与机制修饰，**不提供羁绊标签** |
| **奇点槽 (Singularity)** | `Slot_Singularity` | 超武融合物 / 概念级特性 | 专属顶级词条槽 |

### 1.2 插槽数量矩阵

| 权能等级 | 核心槽 | 作战槽 | 通用槽 | 奇点槽 | **进阶阶总数** | 基础阶总数 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Level 1** | **2** | 1 | 0 | 0 | **3** | 2 |
| **Level 2** | **2** | 1 | 1 | 0 | **4** | 3 |
| **Level 3** | **2** | 2 | 1 | 0 | **5** | 4 |
| **Level 4** | **2** | 2 | 1 | 1 | **6** | 5 |

**基础阶统一比进阶阶少 1 槽**，锁定的是该等级价值最高的那一个（Level 1~2 锁第 2 核心槽；Level 3 锁第 2 作战槽；Level 4 锁奇点槽）。详见 [D-17 正交分级模型](DESIGN_DECISIONS.md)。

### 1.3 为什么核心槽恒为 2、不随权能等级增长

这是本矩阵最关键的一条，有意为之：

| 理由 | 说明 |
|---|---|
| **保障羁绊 (6) 档可达** | `5 人 × 2 核心槽 = 10 个身份槽`，(6) 档需要 6 件同标签 → 可达。若核心槽仍为 1，全队职业词条上限只有 5 件，**6 条职业羁绊的 (6) 档会全部成为死代码** |
| **低星素体不被排除在构筑之外** | 若核心槽随等级增长，Level 1 垫脚石将无法参与羁绊凑件，与 [HERO_VESSEL](HERO_VESSEL_SYSTEM_SPEC.md) 定义的"高流动性垫脚石"生态位直接矛盾 |
| **权能等级的经济意义改为体现在广度** | 高星买的不是"能不能参与构筑"，而是**"我还能额外带多少东西"**（作战 / 通用 / 奇点），以及 Level 3~4 独享的转译与拦截权能 |

### 1.4 核心槽的取舍张力

职业与血脉**共用同一批 10 个核心槽**，这构成本系统最主要的构筑决策：

| 目标 | 核心槽开销 | 剩余 |
|---|:---:|---|
| 职业 (6) | 6 | 4 → 刚好够一条血脉 (4) |
| 职业 (4) + 血脉 (4) | 8 | 2 → 可再挂一条职业 (2) |
| 职业 (2)×2 + 血脉 (4) | 8 | 2 |
| **职业 (6) + 血脉 (4)** | **10** | **0 —— 完美构筑上限，零冗余** |

**`职业(6) + 血脉(4)` 恰好用满 10 个核心槽**，这是理论最优解且没有任何容错空间。这个"够得着但必须精确"的天花板是刻意设计的。

### 1.5 羁绊件数上限速查 **[推导]**

| 词条类别 | 承载槽位 | 全队槽位数 | 档位阶梯 | 投入形状 |
|---|---|:---:|:---:|---|
| 职业词条 | 核心槽（与血脉共用） | 10 | `(2)/(4)/(6)` | **纵深** |
| 血脉词条 | 核心槽（与职业共用） | 10 | `(2)/(4)` | **广度** |
| 技能词条 | 作战槽 | 5 ~ 10 | 见各词条 | — |
| 超武 | 奇点槽 | 0 ~ 5 | 仅 Level 4 进阶阶 | — |

#### 1.5.1 职业有 (6) 档、血脉没有 —— 这是刻意的不对称

两类词条抢同一批 10 个核心槽，但奖励**相反的投入形状**：

- **职业奖励纵深**：押 6 件（60% 身份槽）在单一流派上，换取 (6) 档的全队级质变；
- **血脉奖励广度**：每套堆到 4 件即封顶，第 5 件的正确去处是**下一套血脉**。

```
蜀山(4) + 赛博(2) = 6 件 —— 两套同时激活，零浪费
蜀山(4) + 赛博(4) = 8 件 —— 两套均达大共鸣
```

玩家永远不会把第 5 件投进同一套血脉（收益为零），而是自然转向第二套。**取舍由阶梯结构本身引导，不需要为血脉补 (6) 档。**

由此产生的构筑张力是清晰的：**要么职业走深（`6+4`）压缩血脉空间，要么血脉铺广（`4+4`）放弃职业大羁绊**。

### 1.6 开局保底规则 ✅ [D-08b](DESIGN_DECISIONS.md)

初始大名单中每个素体，进局时默认在**第 1 核心槽**预装 1 枚对应职能的 Lv1 基础职业词条，绝无"裸奔无职"的真空期。第 2 核心槽开局为空（基础阶锁定），由玩家自行填入职业或血脉。

### 1.7 词条强类型数据模型

```json
{
  "affix_id": "affix_cyber_nano_blade_01",
  "name": "高频纳米振动刃",
  "slot_type": "Combat",
  "quality": "Rare",
  "tags": ["Cyber"],
  "affinity": ["Striker"],
  "stats": {
    "AtkFlat": 45,
    "AtkMult": 0.05
  },
  "passive_behavior": {
    "trigger": "OnNormalAttackHit",
    "effect": "ApplyBleed",
    "params": { "proc_chance": 0.20 }
  },
  "fusion_target": "affix_super_concept_cutting"
}
```

### 1.8 ⚠ `tags` 与 `affinity` 的区别（羁绊计数的唯一口径）

这是最容易实现错的一处，必须严格区分：

| 字段 | 作用 | 是否计入羁绊件数 |
|---|---|:---:|
| **`tags`** | 该词条**贡献**的羁绊标签 | ✅ **计入** |
| **`affinity`** | 该词条**偏好搭配**的职业，仅用于 UI 推荐与「一键推荐战术」 | ❌ **不计入** |

**硬规则**：

```
职业羁绊件数 = 仅统计【核心槽】内职业词条的 tags
血脉套装件数 = 仅统计【核心槽】内血脉词条的 tags
作战槽 / 通用槽 / 奇点槽的词条 → 不贡献羁绊标签
```

> ⛔ **不得让技能词条携带职业标签并计入羁绊**。若允许，职业词条上限会从 10 件（核心槽）膨胀到 20 件（核心 + 作战），[D-25](DESIGN_DECISIONS.md) 的全部推导与 (6) 档的"60% 身份槽投入"代价设定将同时失效。
>
> 本节前一版的示例曾写 `"tags": ["Cyber", "Striker"]`，其中 `Striker` 应为 `affinity`，已更正。

**世界标签（`Cyber` / `Shushan`）的归属**：血脉词条通过 `tags` 贡献世界标签用于套装共鸣；技能词条的世界标签**仅用于超武融合的配方匹配**，不计入套装件数。

## 二、六大基础职业羁绊规格

羁绊按全队上阵素体装备的该职业词条**总件数**计算档位。

**生效范围规则** ✅ [D-08a](DESIGN_DECISIONS.md)：
- **(2) 件档位**：仅对佩戴该职业词条的单位生效；
- **(4) 件档位**：仅对佩戴该职业词条的单位生效，效果质变；
- **(6) 件档位**：**全队所有 5 名出战单位无差别全额生效**。

**可达性** ✅ [D-25](DESIGN_DECISIONS.md)：核心槽扩容至每素体 2 个后，全队共 10 个身份槽，`(6)` 档需投入 **60% 的身份槽位**在单一流派上——够得着，但代价明确。**[推导]** 可行的档位组合：`6+4`、`6+2+2`、`4+4+2`、`4+2+2+2`、`2×5`。

> ⚠ **配平观察项**：`(6) + (4)` 现在可以**同时开启**（如守卫(6) 全队 40% 减伤 + 强袭(4) 30% 穿甲）。数值类效果由 [D-13 软钳制](#六数值防爆与软钳制规范-d-13)兜住，但**机制类效果兜不住**——暗影(6) 的 20% 阈值斩杀、守卫(6) 的全队免死均不是乘区，不受上限约束。这两条需单独复核（见 [BATTLE_CORE 附录 B-16](BATTLE_CORE.md)）。

| 职业羁绊 | 标签名 | (2) 档位效果 (装备者生效) | (4) 档位效果 (装备者生效) | (6) 档位终极效果 (全队生效) |
|---|---|---|---|---|
| **守卫 (Guardian)** | `Guardian` | 护甲提升 25%，每秒获得相当于自身最大生命 2% 的护盾（上限 20%）。 | 护甲提升 60%，每秒自然回复 5 点法力 (`ManaRegenPerSec = 5`)。 | **坚壁共鸣**：全队常驻获得 40% 减伤；**全队共享 1 次**免死——首个受到致命伤害的友军保留 1 点生命并获得 1.5 秒无敌，**该单位战斗结束后仍转入重伤**（✅ [D-27](DESIGN_DECISIONS.md)）。 |

| **游猎 (Ranger)** | `Ranger` | **对敌方后排目标伤害 +25%，且普攻可直接索敌敌方后排**（不再受前排优先规则约束）。 | 普攻有 35% 概率触发连击（立即追加一次 70% 伤害的普通攻击）。 | **箭雨风暴**：全队 `Speed` 提升 40%；友方后排单位的所有攻击自动索敌敌方血量最低的目标。 |
| **暗影 (Shadow)** | `Shadow` | 战斗开局进入隐匿 3 秒（无法被选为单一目标，**主动出手后立即解除**），首次攻击造成 200% 伤害。 | 每次击杀使自身重新进入隐匿 2 秒，背刺（攻击敌方后排）伤害提升 50%。 | **寂灭终焉**：全队造成伤害的 15% 转化为生命吸取（**DOT 与反射不触发吸血**）；敌方单位生命低于 **12%** 时，被**直接伤害**（普攻/战技/大招）命中即斩杀——**DOT 不触发斩杀**（✅ [D-27](DESIGN_DECISIONS.md)）。 |

### 2.2 经典机制的词条化回归 ✅ [D-26](DESIGN_DECISIONS.md)

D-26 采用标准六职业原型后，v1.0 的三条标志性机制不再是职业天赋。**它们全部作为技能词条（作战槽）回归**，玩家自行刷取与搭配。

#### 设计立意

> **定位清晰度由职业承担，记忆点由词条承担。**

把记忆点放在词条上比放在职业上更适合肉鸽——词条可刷取、可组合、每局重新发现，而职业天赋是开局就固定拥有的。此外，词条化还顺带解决了这三条机制在 v1.0 中的原生缺陷（见各条备注）。

#### 三条回归词条

| 词条 | `affix_id` | 承载槽 | 效果 | Lv1 / Lv2 / Lv3 | 挂钩点 |
|---|---|:---:|---|:---:|---|
| **狂化涌流** | `affix_berserk_surge` | 作战槽 | 攻击力随已损失生命线性提升：`Atk × (1 + K × (1 - HpRatio))` | `K = 0.30 / 0.45 / 0.60` | `GetAtkMultiplier` |
| **疾风连动** | `affix_swift_cascade` | 作战槽 | 出手结算后有概率重置满行动条立即再出手，**额外再动不产生法力与怒气** | `15% / 22% / 30%` | `RollExtraAction` |
| **裂伤箭镞** | `affix_rend_barb` | 作战槽 | 普攻命中时有概率施加【流血】 | `15% / 20% / 25%` | `OnAfterAction` |

**Lv3 上限刻意对齐 v1.0 的原始数值**（+60% / 30% / 25%），使满阶词条等价于当年的职业天赋——老玩家的肌肉记忆得以保留，同时新玩家需要投入才能获得。

#### 各条的备注与修正

**狂化涌流** —— 词条化顺带修掉了一个原生冲突。v1.0 中残血增伤是近系的**强制天赋**，与 `LowestHpAlly` 治疗 AI 直接互相拆台（治疗师会持续自动地消除你的增伤）。改为可选词条后，这个矛盾从"系统强加"降级为"玩家自担"——你自己选择走不走这条路。默认 AI 仍建议对携带本词条的单位施加治疗权重折扣（见 [BATTLE_CORE 附录 B-10](BATTLE_CORE.md)）。

**疾风连动** —— **必须保留"额外再动不产能"这条款**，它不是文案而是关键护栏。[推导] 概率 `p` 时期望出手 `1/(1-p)` 次；`p = 30%` 时出手 `+43%`，但由于不产能，技能释放速率 `= (Speed/200)/5` 次/秒**与不带此词条时完全相同**。即 `+43%` 全部加在普攻上，技能次数零增益。若去掉该条款，速度流会因"技能次数也 +43%"而立刻失控。

**裂伤箭镞** —— 流血的具体数值走 [BATTLE_CORE 14.3](BATTLE_CORE.md) 的统一定义（`6s / 2s一跳 / MaxHp 5% + Atk × 0.20`），**词条只负责触发概率，不覆写状态参数**。

> ⚠ 已修正：`affix_cyber_nano_blade_01`（高频纳米振动刃）原写 `"dot_rate": 0.08, "duration": 3.0`，与内核流血定义冲突——3 秒配 2 秒跳间隔只能跳 1 次，且 8% 与 14.3 的 5% 不符。已改为只声明 `proc_chance`。**所有施加状态的词条一律只声明触发概率，状态参数由内核统一定义**，避免同名状态在不同词条上行为不一致。

#### 与职业的搭配示例（`affinity` 字段用途）

| 词条 | `affinity` | 典型构筑 |
|---|---|---|
| 狂化涌流 | `Striker` / `Shadow` | 强袭走极限输出；暗影配合斩杀线滚雪球 |
| 疾风连动 | `Shadow` / `Ranger` | 暗影刷隐匿触发次数；游猎叠加 (4) 档连击 |
| 裂伤箭镞 | `Ranger` / `Mystic` | 游猎补上 DOT 流派的职业侧锚点，配合战术指令 `T_SPREAD_BLEED` 扩散 |

游猎的三档羁绊（射程 / 连击 / 攻速）本身不含 DOT，**裂伤箭镞正是给"远程物理 + DOT 扩散"这条流派补上的缺口**。

## 三、首发两大世界血脉套装

首发两大世界（D-03）：**蜀山断裂仙界 (Shushan)** 与 **赛博霓虹蜂巢 (Cyber)**。

### 3.1 蜀山仙剑血脉 (`Shushan`)
- **(2) 剑意初成**：装备者释放技能或大招后，在身侧凝聚 1 枚灵气飞剑。飞剑在下一次普攻时协同射出，造成等同于自身攻击力 80% 的物理剑气穿刺伤害。
- **(4) 万剑归宗**：飞剑上限提升至 5 枚。当集齐 5 枚飞剑时，自动融合成一柄【巨阙虚影】轰击敌方密集区域，造成 400% 范围真实伤害并眩晕目标 1.5 秒（计入控制递减）。

### 3.2 赛博蜂巢血脉 (`Cyber`)
- **(2) 纳米覆甲**：战斗开局获得相当于自身 35% 最大生命的纳米能量屏障。屏障存在期间，免疫灼烧与流血等 DOT 伤害。
- **(4) 矩阵过载**：当生命值首次跌破 50% 时，进入持续 6 秒的【算力过载】状态：**充能倍率 `GaugeRate` +100%、受到伤害 -40%**，期间普攻附带高频电弧跃迁。

> ⚠ 原设计的「所受伤害延后 4 秒结算」已裁剪（✅ [D-27](DESIGN_DECISIONS.md)）——待结算伤害池与确定性、DOT、死亡判定三方交互，是全部候选机制里风险最高的一项。改为「受到伤害 -40%」，保留同样的"爆发窗口"观感。

## 五、词条背包与装卸流通规则

### 5.0 ⚠ 术语区分：精炼 / 分解 / 融合

三个操作曾在不同文档中混用同一个词，此处统一定名，**其他文档一律以此为准**：

| 操作 | 英文 | 输入 → 输出 | 场所 |
|---|---|---|---|
| **精炼** | `Refine` | 2 枚同名同阶词条 → 1 枚高一阶词条 | 安全屋 |
| **分解** | `Salvage` | 1 枚词条 → 信用点 | 任意（背包溢出时可就地执行） |
| **融合** | `Fuse` | 2 枚满阶跨界词条 → 1 枚超武 | 安全屋 / 跨界裂隙 |

> ⛔ **禁止用"精炼"指代分解**。[ROGUE_WORLD 4.2](ROGUE_WORLD_AND_AFFIX_DRAFT.md) 与 `IInventoryService.Refine(a, b)` 已将"精炼"定义为**升阶合成**，本文档 v1.0 曾用它指代"分解换信用点"，已在此更正。

### 5.1 背包容量与溢出结算 ✅ [D-16](DESIGN_DECISIONS.md)
- **备用背包容量**：固定 **15 格**；
- **溢出处置**：当战斗掉落或事件获取新词条且背包已满（15/15）时，界面弹出【就地取舍】弹窗：
  1. 丢弃多余词条；
  2. 将选定词条就地**分解（Salvage）**，转化为对应品质的信用点（普通 15 / 稀有 35 / 史诗 80）。

> **为何由 10 格上调至 15 格** ✅ [D-25](DESIGN_DECISIONS.md)：核心槽扩容后，全队装备位从 `10~20` 上升至 `15~30`（+50%）。若备用背包仍为 10 格，其相对容量缩水近半，会导致**超武融合（需同时囤 2 组满阶素材）几乎无法操作**。15 格与装备位同比例放大，维持"背包 ≈ 半个队伍的词条量"的手感。

### 5.2 拔插装卸时机 (D-14)
- **安全节点（安全屋 / 黑市）**：允许玩家无限制、无代价地在素体插槽与备用背包之间自由装卸、拔插、调换词条；
- **行军途中（常规遭遇、高危遭遇、位面异象途中）**：所有素体插槽**强制锁定**，禁止临时调换配装，玩家必须依靠战前规划的构筑迎战。

> **[补全]** 节点名称统一使用 [ROGUE_MAP 1.4](ROGUE_MAP_AND_RECRUITMENT.md) 的六种官方命名：**常规遭遇 / 高危遭遇 / 位面异象 / 黑市 / 安全屋 / 位面守望者**（另加跨界裂隙）。不得再使用"营地 Rest""行商 Shop""精英战"等别名。

### 5.3 重伤流通规则 (D-09a)
- 素体阵亡进入【重伤】状态后，仅该素体无法出战；
- **其插槽上的词条绝不锁定**。玩家可以在安全节点将重伤素体身上的词条卸下，重新装配给其他替补健康素体，避免构筑资产因偶发战损而连带瘫痪。

## 六、数值防爆与软钳制规范 (D-13)

为杜绝无限流肉鸽在后期产生"数值破表导致战斗死机或秒杀 Boss"的崩塌，战斗计算层引入严格的**软钳制（Soft Cap）管线**：

```csharp
public static class BalanceCaps
{
    // ── 硬上限 (Cap)：任何构筑都永远无法触及 ──
    public const float MaxDamageReduction     = 0.75f;  // 总减伤率上限 75%
    public const float MaxGaugeRate           = 3.00f;  // 行动条充能倍率上限 300%
    public const float MaxAttackMultiplier    = 5.00f;  // 攻击总乘区上限 ×5.0
    public const float MinHealingReceived     = 0.20f;  // 受治疗系数下限 20%（重伤类减疗的地板）
    public const float MaxHealingReceived     = 3.00f;  // 受治疗系数上限 300%
    public const float MaxDotPercentHpPerSec  = 0.15f;  // 全 DOT 合计每秒扣血上限 15% MaxHp

    // ── 软阈值 (Soft)：低于此值不受任何惩罚 ──
    public const float SoftDamageReduction    = 0.50f;
    public const float SoftGaugeRate          = 2.00f;
    public const float SoftAttackMultiplier   = 3.00f;
    public const float SoftHealingReceived    = 2.00f;
    public const float SoftDotPercentHpPerSec = 0.10f;

    /// 软钳制：软阈值以下恒等，仅衰减超出部分，渐近但永不触及 Cap。
    public static float SoftClamp(float raw, float soft, float cap)
    {
        if (raw <= soft) return raw;                    // 低值区不惩罚
        return soft + (cap - soft) * (1f - soft / raw); // 阈值处连续
    }
}
```

### 6.1 钳制算法与验算

**规则**：软阈值以下**完全不惩罚**，只对**超出部分**做双曲衰减。

$$f(x) = \begin{cases}
x & x \le \text{Soft} \\[6pt]
\text{Soft} + (\text{Cap} - \text{Soft})\left(1 - \dfrac{\text{Soft}}{x}\right) & x > \text{Soft}
\end{cases}$$

以攻击总乘区（`Soft = 3.0`, `Cap = 5.0`）验算：

| 原始乘区 | 生效乘区 | 说明 |
|---:|---:|---|
| 1.00 | **1.00** | 无任何加成时不受惩罚 |
| 2.00 | 2.00 | 软阈值内线性 |
| 3.00 | **3.00** | 阈值处连续，无跳变 |
| 4.00 | 3.50 | 超出部分开始衰减 |
| 6.00 | 4.00 | |
| 12.00 | 4.50 | |
| → ∞ | → 5.00 | 渐近，永不触及 |

保证构筑永远有正向提升，但永远不会击穿战斗时钟底线。

### 6.2 ⚠ 不可采用的错误形式

v1.0 草案曾使用下列作用于**整体**的形式，**已废弃**：

$$f(x) = \text{Cap}\left(1 - \frac{1}{1 + x/\text{Cap}}\right) \quad \text{❌}$$

代入 `Cap = 5.0` 验算可见两处致命缺陷：

| 原始乘区 | 错误形式的结果 | 问题 |
|---:|---:|---|
| 1.00 | **0.83** | **无任何加成时凭空削弱 17%** |
| 5.00 | **2.50** | **堆到 Cap 值时只拿到一半** |
| → ∞ | → 5.00 | 只有无穷大才逼近 Cap |

任何软钳制实现必须同时满足两条性质，否则视为错误：

1. **低值区恒等**：`raw ≤ soft` 时 `f(raw) = raw`；
2. **阈值处连续**：`f(soft) = soft`，不得出现跳变。

### 6.3 钳制施加位置

> ⚠ **钳制必须在内核出口统一施加，`Modifier` 侧不得自行钳制**。否则多个来源叠加时上限会被重复施加，导致实际数值远低于预期。
>
> 各乘区的挂钩点与钳制位置见 [BATTLE_CORE 12.5 与 13.2](BATTLE_CORE.md)。
